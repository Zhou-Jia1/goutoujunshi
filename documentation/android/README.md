# 狗头军师 Android 版：升级规划总览

规划日期：2026-10-31（同日修订为「全场景聊天军师」，并加入「悬浮军师」）
状态：**开发中**。用户已确认 [05-规划审查与修订建议](05-规划审查与修订建议.md) 的 R01–R12，修订已纳入 01–04。本目录描述目标与验收契约，不表示功能已经实现；工作包状态及证据以开发记录为准。

## 一句话目标

**教不会聊天的人和任何人好好说话，而且说出来像自己。**

用户上传和领导、同事、暧昧对象、伴侣、家人、朋友的聊天记录，或者在聊天时点一下悬浮球，军师结合知识库读懂局面，给出当前场景下对用户目标最有利的处理方式，以及一句符合用户本人风格、可以直接发送的回复，并告诉用户为什么这样说更好。

## 分工

| 角色 | 负责 | 不负责 |
| --- | --- | --- |
| **Codex** | 安卓工程、业务逻辑、数据层、模型接入、导入与 OCR、风格画像、悬浮军师、记忆、测试，新增知识文档的初稿，以及全部页面的**功能性搭建** | 视觉风格细节。页面只能使用 `core/designsystem` 中的令牌和组件 |
| **Claude** | `core/designsystem`：主题令牌、组件外观、插画、图标、动效、深色模式、悬浮球与面板的外观，以及页面级视觉验收与美化 | 业务逻辑与数据结构 |
| **项目负责人** | 选择模型服务商、审阅知识文档和安全词库、复核求助热线、确认隐私政策和上架合规、验收每个里程碑 | — |

协作约定：

1. Codex 在 M1 先按 [04-视觉设计系统](04-视觉设计系统.md) 的令牌值和组件签名建出可用的基础版 designsystem；视觉不必精细，但**组件签名必须与文档一致**。
2. 之后 Claude 只改 `core/designsystem` 和图片、图标等资源，不改页面中的业务代码。需要调整页面布局时，Claude 提交独立 PR 并说明原因。
3. 每个里程碑结束时，Codex 输出关键页面截图（见任务书 T-QA），Claude 据此做视觉审查。

## 需要项目负责人决定的事项

1. 模型服务商，以及是否提供官方网关（影响费用和合规义务）。
2. 应用 ID（暂定 `com.shengjidaguai.goutoujunshi`）。
3. 审阅新增知识文档、平静与危机关键词库；复核 110 和 120 以外的求助热线。
4. 上架合规：生成式 AI 服务备案；悬浮窗与屏幕录制的用途说明；隐私政策。
5. 是否需要单独规划鸿蒙版（HarmonyOS NEXT 无法安装安卓 APK）。
