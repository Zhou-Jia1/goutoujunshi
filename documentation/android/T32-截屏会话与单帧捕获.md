# T32 截屏会话与单帧捕获

分支：`android/T32-single-frame`；基线：`e9e11ffb37382b39614de5361c4c435dc684bac2`（T31）。本记录描述 T32 实现与证据，不代表 M3 或整个 App 已完成。

## 实现

- 系统同意后，Activity 仅把不透明 ticket 放进 Service Intent；授权 Intent 放在一次消费的进程内 ProjectionGrantStore。投屏结果使用平台 onActivityResult 独立请求码，避免 ActivityResultRegistry 保存未投递的原始投屏结果。Activity 重建不恢复 ticket；旧 Activity 不能授权或撤销新请求。
- Service 先进入 mediaProjection 前台服务，再 getMediaProjection、registerCallback，最后每会话仅 createVirtualDisplay 一次。平时 surface=null。单击球或无障碍单击执行捕获，长按打开控制页；拖动与位置保存沿用 T31。
- 每次点击隐藏控制/确认窗口和球，等待两次 Choreographer 刷新，换用全新 ImageReader，再接既有 VD。这样旧 Reader 队列不会混入下一次点击；不依赖不同来源的 timestamp 时基相同。取到独立 Bitmap 后立刻暂停 VD 并恢复球。
- 直接 Bitmap 入口仍调用隔离 Paddle 服务，沿用其最多两个资源 lease 和取消/关闭机制；不编码临时 PNG、不经文件 Provider、不上传截图。原始 Bitmap 在识别成功/失败/取消后回收；交接取消时亦回收尚未被接收的帧。
- 均匀黑色/深色空白按“暂时没能读取画面”处理，不把黑色当成受保护的证据。暗色画面含可见像素仍可 OCR。无新帧、不可见共享范围、OCR 失败均提供检查共享范围、重试、复制可分享文字或导入文件的退路，不自动触发模型。
- 屏幕关闭、系统投屏停止、授权撤销/接管、主动停止、超时共用幂等清理。Reader/Image/VD/投屏、捕获 job、在途 preview、通知与球窗口均按所属 ticket 清理。旧已排队 onStop 不会停止替代会话。旋转/单 App 尺寸回调 resize 既有 VD，不创建第二 VD。
- 超时默认 10 分钟，可选 5/10/30；控制页显示当前值。任何停止后必须由 App 或 Tile 重新触发本次系统授权。
- 首张捕获认领新的临时上下文。Controller actor 在原 authority 与 capture generation 都有效时，原子递增 epoch 并切换临时上下文，再交回 claimed authority。手动/分享导入和停止与该认领互斥；晚返回不能覆盖后来的上下文。
- OCR 文本复用 T22 ImportPreview 的左右身份、低置信度、排除行、权利与目标确认。下一次“向上截一屏”在同一 RAM preview 前插新页，并复用 OcrLayout.adjacentOverlap 去重。未确认前不读联系人记忆、不把旧答案当作新截图上下文。确认后仍经原有导入、知识库、统一脱敏、冻结真实 JSON 发送预览链；T32 不新增模型旁路或隐式摘要调用。

## 单 App 授权回传与锁版本

实际设备证明系统选中单 App 后会把目标任务带到前台。原 decorView.post + RESUMED 检查会丢掉已同意的 grant；现在发起系统 consent 仍必须由 RESUMED owner 完成，但本次有效 OK 结果会同步交前台服务，保留 ticket、独立 projectionLockRevision、最新锁/悬浮权限以及 finishing/destroyed 校验，不强行把宿主带回前台。锁版本随 Intent 只存一次消费的 RAM holder，Service Intent 仍只有不透明 ticket；Service 接收和发布 active 前再核验，锁定后解锁也不能重签旧 grant。异常路径清当前 owner 的 holder。

## 旋转时在途单帧与 owner 清理

排查单 App 旋转超时时，JVM 回放独立确证了 resize 会取消在途 waiter 的问题。resize 现在保留同一 active waiter，换新 generation Reader、resize 既有 VD，再接新 Surface 继续这一点击；idle 仍为 null Surface。错误/停止/取消会幂等清理，旧 generation 帧仍丢弃。系统停止先撤销 owner 权限再释放 waiter，避免 stop 过程中先发布迟到结果。对应真实 RED：`R:/task-tmp/t32-pending-resize-red.log` 与归档 XML，两项断言失败后修正。平台上持续的旋转超时后来由固定计数证明是第二次点击未到球；不能把该平台超时写成 resize 缺陷的直接证据。

补充进程与旧 owner 边界：fresh RAM session 不可因从 1 重新计数而重新承认旧 task Intent 的 ticket，epoch 初值使用仅进程内的随机 namespace；不持久化、不恢复旧授权。`R:/task-tmp/t32-process-authority-red.log` 已独立复现旧票重新有效。旧 Service 清理也不可把后来 REQUESTING_PERMISSION 改 OFF（`R:/task-tmp/t32-old-cleanup-state-red.log` 真实失败）；全局 FSM 撤权只由 FloatingSession.stop/cancel 执行，资源清理保持所属 owner，Runtime.stop 先撤权再取消 waiter。
