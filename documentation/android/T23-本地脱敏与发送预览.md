状态：实现与合成自动化验证中；不代表真实服务商、真实 Key 或实体设备验收。

## 发送边界

所有请求通过 `PromptBuilder` 装配 canonical `SKILL.md`、当前场景与 1–3 份带哈希的参考资料。公共系统知识保持原文；用户文字、确认后的证据与说话人昵称、联系人背景、摘要、风格描述与样本、原答案 JSON 字符串叶子，以及只读 `actualDataContext` 均经过同一个请求内 Redactor。用户区域始终转义为数据，规则不能改写系统伦理或安全指令。额外上下文的来源联系人和样本来源必须与当前联系人一致（无联系人来源的样本可用）；未确认或串线证据拒绝装配。

`OutboundRequests` / `OutboundEngine` 提供完整分析、长记录摘要、风格描述、回复改写和对练五个真实入口，共用同一个 provider 和装配器。T26/T41/T52 的完整页面未提前实现。改写仍限定 REPLY/ALT，原答案先脱敏再 JSON 编码；危机升级和过期回调规则保留。预算继续限制输入 4000、额外上下文 4000、风格描述 600、每样本 200/最多 5 条、联系人背景 4000、摘要 2000、证据 12000、总提示词 48000 个码点；最新单条证据过大时失败，不静默清空。

Live 页面展示 `CompletionBody.encode` 的完整实际 JSON（不包括 Authorization），服务商、模型和数据范围，确认后沿用同一 `FrozenPromptAssembler` 快照发送。每次修改隐私规则会立即撤销预览、在途回调和重试；必须重新预览。原有 Key/config/revision/origin 一致性校验保留。

## 本机规则与显示

自动识别中国手机号、固定电话、邮箱、18 位身份证、16–19 位银行卡、详细地址和 HTTP(S) 链接，替换成稳定的类型占位符。没有查询真实身份或自动建立昵称关系。用户在「查看实际准备的内容 → 补充屏蔽词与昵称代号」中明确输入原昵称与安全代号，或按行补充公司、姓名等屏蔽词。

原始输入上选取不相交的最长匹配区间，再一次性生成占位符；重叠时同长度优先自定义词、昵称，随后自动类型。不会对生成的占位符再次扫描，因此 `号`、`1`、`屏蔽词` 也不会破坏生成结果。每个请求内同值同类型共用一个编号。未上传原值映射；PreparedPrompt 只有计数与已验证的「昵称占位符 → 安全代号」白名单。

代号最长 40 个 UTF-16 单元，不允许包含任一原昵称、屏蔽词、自动可识别敏感信息、控制字符或 `[]<>`。规则合计最多 100 项，原昵称和屏蔽词每项最长 200 个 UTF-16 单元，空白项拒绝；编辑器按行输入，昵称格式为 `原昵称=安全代号`。限制超过时拒绝保存并提供修复提示。等号后的全部内容作为代号，原昵称不支持含等号的编辑器写法（领域 API 不受此编辑语法限制）。

完成答案仅在人读字段还原白名单昵称代号；手机号、证件、地址、公司屏蔽词及未知占位符始终保持遮蔽。流式 section 原始缓冲区不改；展示时投影累计字段，完整昵称占位符才还原，末尾分片中的已知昵称占位符暂缓展示。ID、消息引用、rawText、记忆提案保持机器表示。

识别规则可能漏检（例如非常规电话、证件、地址写法或未补充的公司/姓名），也可能误判连续数字；不承诺完全去身份化。页面明确提示检查完整发送内容并补充规则。

## 作用域与存储

临时会话的规则与未提交编辑器文字只在进程内普通状态中；离开会话或进程结束后不恢复，不进入数据库、DataStore、文件、Bundle/SavedState。正式联系人规则使用独立 `OwnedRecordKind.REDACTION`，保存于原 SQLCipher 的 owned-record 表，主键含长度和 contactId，必需 FK 删除级联。枚举扩展没有 SQL DDL 或 schema 变化，不增加 Room 版本。保存校验策略 revision 的 CAS；删除联系人和清空数据会删除规则，不产生独立 vault 孤儿。隐私配置独立于风格学习 consent。

联系人来源/origin 与 actor/epoch 门禁保持；旧 A 编辑器事件不能取消或修改 B 请求。保存结果未知时清除旧授权、阻止发送，重新保存前从存储读取 revision 以恢复。
