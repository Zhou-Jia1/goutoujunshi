## 实现契约

「我发了」成功保存正式 ActionPlan 后询问提醒。复选框默认关闭，用户必须明确选一小时后或明天八点并确认；显示按当前时区免打扰规则计算的最早时间，说明系统可能更晚。13+ 仅在本次明确选择后申请通知权限；拒绝显示可关闭说明，零提醒记录、零任务。已有系统授权也不等于本次 opt-in。临时问问不提供后台提醒，不落库、不写 WorkData。浮窗现有紧凑面板没有「我发了」入口，完整 App 分析入口复用此唯一反馈流程，未引入第二套授权。

SQLCipher `owned_records/FOLLOWUP` 是唯一提醒权威；WorkData 只有随机 UUID `id/generation`，WorkManager 一次性 initialDelay、不设联网约束、无 exact alarm、无额外模型调用。时间策略在执行及最终通知 gate 重新核当前时区、DST、原 due；默认 23–08 延至八点且不提前。Worker、时间策略、平台调度/通知、opaque 路由、UI 各自独立；Controller 仅接用户意图和持久化结果。

每次新安排使用独立随机 id/generation；旧安排取消只能取消自己的 unique-work 名称。DataSession 的同一 gate 串行来源变更、取消、通知及全清；事务后复核正式联系人/计划/答案/请求、会话和来源版本、脱敏版本、证据行及来源选择。取消、改期、我没发、删除计划/联系人/来源、全清和发现系统拒权使旧记录失效并移除已显示通知。notify 后 cancel 在同一 gate 补偿移除，不使用单次 check-then-notify；已取消来源不能被旧任务恢复。无完整 state collector 或无条件 cancel/epoch 反馈环。

通知默认通用文案，正文不含代号、聊天或回复。设置末尾可显式开启显示代号；冷启动无可用解锁权威、系统或应用锁定仍用通用文案，应用锁定和关闭代号设置会移除已显示通知。PendingIntent immutable、显式 MainActivity、独立 URI 身份，仅双 UUID；路由重新读现存加密来源并先过统一解锁门禁，不接受 owner 或正文 extras，不通过 loadOrCreate 复活被删资料。有效通知进入联系人对话，显示「上次你发了那条消息，对方回了吗？」及上传新截图／还没回／情况变了；后两者仅填入草稿，不自动模型发送。
