# T55 隐私：应用锁、桌面入口与完整清除

本包扩展同一 CounselController 的 LockState、lockRevision、intentLock 和 RunAuthority。锁偏好不保存 unlocked；Application 在私密 Activity 首帧前同步加载偏好，读取失败按启用锁处理。离开时间使用 elapsedRealtime；Controller 以同一锁版本撤销请求、导入、预览、教学、风格、对练和旧认证票据。立即、1分钟、5分钟期限在后台和返回时检查，时钟异常向后同样锁定。配置重建不当作离开，同 App Activity 交接延至下一主线程消息判定；系统认证、系统权限和选择器使用当前 Activity 的临时离开标记。

## 系统认证与安全窗口

开启需先完成系统认证，未设置系统凭据时显示原有不可用说明并保留关闭状态。API26–28 使用 KeyguardManager 的真实设备凭据 Intent；API29+ 额外提供系统 BiometricPrompt 与设备凭据回退，取消、错误、旧 attempt、旧 lockRevision 和清除版本均不能解锁。认证票据仅 RAM；成功及启用偏好写入共用 intentLock，写入失败不开放私密内容。配置销毁取消当前 attempt，不从 Bundle 恢复成功。

开启期间 MainActivity、FloatingCounselActivity 及实际 WindowManager 答案面板都设置 FLAG_SECURE；面板在 addView 前即有标志，焦点切换保留它。设置明确说明最近任务隐藏以及不能截图。原有 CaptureOwnUi 对主 App 私密像素的拒绝保持。系统截图、最近任务与真实投屏窗口的效果由 root 在精确三 APK 上验证；JVM 截图只验证布局与字号。

官方 API 依据（2026-11-03核实）：[KeyguardManager](https://developer.android.com/reference/android/app/KeyguardManager#createConfirmDeviceCredentialIntent(java.lang.CharSequence,%20java.lang.CharSequence)) 的凭据 Intent 自 API21 可用，API29 起 deprecated 但仍是兼容路径；[BiometricPrompt.Builder](https://developer.android.com/reference/android/hardware/biometrics/BiometricPrompt.Builder#setDeviceCredentialAllowed(boolean)) 的设备凭据选项自 API29 可用；[FLAG_SECURE](https://developer.android.com/reference/android/view/WindowManager.LayoutParams#FLAG_SECURE)；[activity-alias](https://developer.android.com/guide/topics/manifest/activity-alias-element)。没有新增认证库或统计 SDK。新增 USE_BIOMETRIC 是普通权限；危险权限与技术依赖的实际清单以归档 merged Manifest 为准。

## 清除协议

Controller 同步递增 clearRevision、authenticationId、lockRevision 和请求 epoch，立即撤私密 UI、网络及其他 RAM 权限，再通过 actor 清除持久状态。EncryptedDataStore 先写耐久 cleanupPending，再在同一 DataSession gate 设置 active=false；取消提醒、执行平台 stop，finally 关闭数据库。即使提醒端口或平台 stop 抛错，后续 stop 与数据库关闭仍执行，marker 保留供重启重试。

平台 stop 撤导入、WorkManager 跟进 tag、系统通知、MediaProjection、WindowManager、前台服务与其通知；T54 的系统 cancelAll（覆盖已 accepted 尚未 posted 的通知）和同一 display monitor 保持。随后删除 junshi.db/WAL/SHM/journal、正式来源文件、密钥包装与 Keystore key，再清 import-notice、followup-settings、style-bias、privacy、浮窗位置偏好及 App cache/codeCache，恢复默认桌面入口。最后成功后才移除 marker。冷启动 pending wipe 先补完相同平台/偏好步骤再 open，旧 DataSession 永久失效；知识 assets 不删除。

本包不在全清时改写系统剪贴板，因此不会清除外 App 后来复制的内容。现有复制敏感标记保持。完整清除的生产入口位于「我的 → 应用锁与隐私」，原有设置清除入口复用同一 ViewModel/Controller 协议。
