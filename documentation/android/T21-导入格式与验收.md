# T21 · 聊天记录导入格式与验收

全部示例均为虚构。T21 接收分享、用户点击粘贴和 SAF 文件；图片只保留当前进程的 URI，当前不识别、不上传。OCR 属于 T22。未使用真实 ChatLab 导出夹具验证，因此**不宣称兼容任何 ChatLab 版本**。

## 支持的文件

UTF-8 TXT/JSON，可含 UTF-8 BOM。单次输入最多 2 MiB、2000 条消息；严格解码，非法 UTF-8 拒绝，不猜测编码。通过 ACTION_OPEN_DOCUMENT 打开 content URI，在内存中限量读取，不复制到文件、不取得永久 URI 权限，不申请广泛存储权限。

TXT 支持 `昵称：消息`、`昵称: 消息`、`2026-10-31 09:20 昵称：消息` 和 `昵称 2026-10-31 09:20` 后换行写正文。后续无标题行作为多行正文。无法确定来源的整段文本保留为未确认消息；所有昵称只是建议，必须逐条选择我/对方/其他人。其他人必须有昵称，群聊成员名称始终保留。

应用自有 JSON v1 格式：

```json
{"format":"junshi-chat","version":1,"messages":[
  {"name":"虚构甲","text":"明天一起讨论？","sentAt":"2026-10-31 09:20"},
  {"name":"虚构乙","text":"可以。"}
]}
```

`messages` 为非空数组，每项的 `text` 是非空字符串；`version` 必须为 JSON 整数 `1`，字符串 `"1"` 不接受。`name`、`sentAt` 可省略或为字符串/null；提供其他类型明确报格式错误。JSON 内声称的 `speaker`/确认状态不可信，解析器不会自动确认。其他格式、未知版本及损坏 JSON 明示为“未验证的原文预览”，须整理内容并确认说话人后才能导入。合成夹具在 `android/app/src/test/resources/imports/`。

## 隐私与状态边界

首次成功导入前展示一次使用权及隐私提示，仅保存提示接受 bool；清除全部数据会重置。待确认文本、图片 URI、预览编辑仅在进程内存中，禁止 Bundle/SavedState/日志/文件/数据库。Activity 冷启动和 onNewIntent 消费分享后立即清空 extras、clipData、data 和 action，旋转不会重放；新的显式相同分享仍会进入确认流程。

用户明确选择临时问问、现有联系人或新联系人，并逐条确认说话人后保存。临时导入只在 TemporarySessionStore，进程死亡即丢失；正式导入通过 ImportRepository 写入加密库。SHA-256 基于最终确认的昵称/消息/时间/说话人，按联系人去重，临时导入按当前会话去重。事务检查联系人 sourceRevision；成功后重新加载联系人与证据，重复保存/确认回执丢失后的重试不重复导入。

导入后，ChatLine 通过 EvidenceBlock 进入实际 AnalysisRequest；不会写入用户问题，也不会成为系统指令。真实 PromptBuilder 仍校验知识完整性、说话人及联系人归属，转义证据内容，演示提供方也经过同一组装器。待确认期间控制器拒绝预览/分析。

## 验证入口

- ChatImportParserTest：常见格式、多行/群聊、JSON v1/未知/损坏、UTF-8/BOM、大小及行数、确认门禁、内容哈希。
- ImportCoordinatorTest：初始化前冷分享、显式相同分享再次接收、消费后重复读取不重放、多文本/图片路径、粘贴不改草稿、私有 file URI 拒绝。
- CounselControllerTest：真实请求 evidence、临时去重及零落库、正式回执失败后重试/重载/sourceRevision、切换联系人后的迟到保存。
- RepositoryTest：事务 CAS、按联系人去重、重载确认消息和群成员名称。
- KnowledgePipelineTest：确认 OTHER 群成员名称、提示注入转义及知识引用。
- ImportScreenshotTest：实际导入预览及读取错误截图；仅对此类运行 recordRoborazziDebug，避免重录历史截图。

最终 Debug APK 为 35,042,569 字节，SHA-256 `259879ada793ec24b48225a37ebfae1b6a249abfe31d0196f89b9524bb61632d`。在独立 Android 15 / API 35 AOSP 模拟器上，`scripts/smoke_android_import.py` 实际得到五项 PASS：

1. 冷启动分享进入目标与说话人确认，确认前不能导入。
2. 显式分享相同内容再次进入预览，确认后按当前临时会话去重并提示。
3. 不填写用户问题，仅凭已确认聊天证据完成知识前置的演示生成及原生复制。
4. force-stop 后临时证据消失，发送预览提示需要输入。
5. 新建合成正式联系人，导入后终止进程，重启仍可用加密恢复的证据分析；结束时仅删除该合成联系人。
