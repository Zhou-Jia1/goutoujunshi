# T24 模型设置与连接验收

默认使用不联网的 Demo。我的页面可选择真实模型、编辑预设或自定义 HTTPS Base URL / 模型 / API Key；必须保存后才能测试。预设不会自动授权联网。

应用复用 `CounselRuntime` 中唯一的 `EncryptedDataStore`、`TemporarySessionStore` 与 `store.vault`。模型设置（包括地址元数据）、密钥和随机 revision 构成同一个记录，使用该 vault 的 Android Keystore AES-GCM 包装；没有新建明文设置 DataStore。保存后 UI 只含掩码及末四位。密钥编辑器使用普通 `remember` 的 `TextFieldState`，退出/保存/清空时抹去编辑内容；不进入 Bundle、SavedState、日志或文件。DS 安全输入额外屏蔽原始 InputText/EditableText 和 autofill 语义，只提供圆点及可访问编辑动作。

修改协议、主机或有效端口时，新原子记录不会带入旧 Key；只有用户显式提供的新 Key 才写给新地址。同一 origin 下的模型/路径修改可保留 Key，但每次保存都会生成新 revision。每个 LIVE provider 的 VaultCredentialSource 捕获完整预期配置与 revision，读取当前加密记录时必须完全匹配，否则不给出密钥、不发 HTTP；读失败亦如此。保存写入可能已提交但 acknowledgement 或最后 readback 失败时，控制器主动替换旧 provider 为阻断的 BYOK provider，清除掩码/预览，并提示重新保存。旧 provider 无法读取新记录的 Key，即使 UI 还保留旧配置快照。代理服务可以由用户明确填写自己的代理 Key。

正式发送先显示服务商主机、模型、数据范围和完整 JSON，再由用户确认。`CompletionBody.encode` 同时产生预览和 HTTP body（不包含 Authorization）。Demo 与真实模型都使用同一个 `FrozenPromptAssembler` 和实际本地知识准备流程。修改输入、切换配置或删除会撤销预览与旧请求。连接测试只发送固定虚构句和本地知识，不读取联系人、草稿、记忆或样本。

真实请求使用 Chat Completions SSE、15 秒连接超时、45 秒首段内容超时；停止或取消调用真实 OkHttp `Call.cancel()`。不自动重试，不重定向，不回退 Demo。错误只呈现固定本地代码/文案，区分认证、限流、服务异常、超时、协议和网络，不呈现可能回显秘密的原始服务商正文。Gateway 只有契约，没有实现。

设置、请求回调、数据库写入及清空由同一控制器 mailbox 串行处理；连接测试另有 generation，清空/设置改变/取消后迟到结果不能恢复旧状态。完整清空同时撤销测试、真实请求、设置和 Key；清空后需显式初始化。每条 assistant 消息持久化 providerKind，旧数据缺省 Demo；重载旧答案的 Demo 标识不随当前模型模式改变。
