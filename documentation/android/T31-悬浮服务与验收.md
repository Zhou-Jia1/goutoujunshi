# T31 悬浮球与悬浮窗服务

本包提供悬浮球、菜单、权限与锁门禁，不新增模型旁路。截屏分析明确禁用；MediaProjection、实际捕获和答案面板留T32–T33。未读其他应用内容、未接统计SDK。

## 实现边界

- FloatingCounselService使用TYPE_APPLICATION_OVERLAY和specialUse FGS；声明对应权限及用途property。通知恒为“悬浮军师已开启 · 点击关闭”，API31+请求即时展示。商店申报/合规仍由负责人确认。
- 只有resumed的非导出Activity发起前台启动，按需申请SAW/通知。Tile34+用immutable自有PendingIntent，低版本显式兼容，系统锁定时unlockAndRun。已有权限时一次点击通过RAM票据交接Activity；无/过期票据、进程恢复、重复resume不自动签新票据/重复启动。
- 票据仅RAM。旧Activity/Service取消只针对owner generation；明确关闭、全清、screen-off全局失效。START_NOT_STICKY，无boot receiver/启用持久标志。只存方向的左右侧/纵向比例，全清时也清除。
- 每个ComposeView有对称lifecycle/ViewModelStore/saved-state owners；window/composition/owners/notification幂等释放。SAW撤权/WindowManager异常清理。
- FloatingBallWindow在Android dispatchTouchEvent入口接管物理手势，避免Compose子树消费后父监听器失效。关闭清空触摸回调，迟到手势不打开菜单或重写偏好。既有DS球负责绘制，app包装保留“打开菜单”的Accessibility OnClick/OnLongClick，DS基线未改。
- 系统touch slop；松手吸边。96dp窗口围绕52dp球，半隐藏仍留48dp可达区域，尺寸来自DS。FLAG_LAYOUT_IN_SCREEN、API30+ fitInsetsTypes=0/cutout模式明确display原点；geometry只应用一次system/cutout insets，避免WM parent重复加status inset。低版本用realMetrics/rootInsets；位置按方向记忆。
- 联系人复用既有Screen/ViewModel/controller，共用LockState/SafetyPolicy。实际系统设备凭据回调绑定RAM epoch/lock revision；无设备凭据静态拒绝。独立解锁只解锁退出，不启FGS。
- Controller唯一权威锁受intentLock保护；普通set合并当前锁，不能从旧state或新session默认值关闭。显式锁操作同步撤销epoch/显示/Job，frozen/recovery/memory等私有清理由mailbox排序执行。
- 模型start/preview/rewrite/retry保留首次挂起前epoch+lock revision authority；挂起返回、run/preview发布、网络任务创建/回执在同一monitor验证。旧操作不能自增epoch重签，锁再解锁也不能复活；最终checkpoint返回后同样检查才发布答案。T55扩展持久化锁设置。
