## 恢复与持久化边界

AnalysisRun 增加可选请求快照、配置 revision 与最高已知安全级别；不更改 Room DDL。快照不含 Key、Authorization、准备后的知识正文或隐私昵称映射副本，仅保存重新构建所需的操作输入及隐私规则版本。恢复从当前联系人规则重新补全，仍由真实本地知识与出站隐私门禁重建提示词。

恢复要求最新用户消息与 run 一致，且会话版本、联系人来源版本、已保存输入、导入证据、隐私规则版本和当前配置 revision 全部一致。过期来源、输入、规则、配置、删除联系人均拒绝恢复。Repository 在同一事务检查联系人来源与会话版本后写 run，删除后不能重建 owner。同一操作（包括错误重试）只升级安全级别；流中安全级别提升时立即写 RUNNING 检查点；最终 Completed 首次提高安全级别，也在助手保存前写入 RUNNING 检查点。失败/重试启动/完成检查点记录最高安全级别，正式恢复读取最后成功写入的检查点。进程在检查点之前突然结束时，尚在内存的新流状态不保证已经持久化。最终危机结果在任何可能失败的存储 IO 之前发布，保存失败时仍隐藏普通回复、全文回退和复制。锁定时整页不显示敏感内容；危机时只显示既有 DS 安全文案，不新增热线。恢复后先落 INTERRUPTED，再提供继续；不会自动调用模型或计费。真实模型须重新显示完整发送预览，并由用户确认；同一操作沿用原 requestId。

失败状态或完成状态写入失败时，重试首先完成存储。已完成的助手保存重试复用现有消息 ID，不再次调用模型；重启如发现对应助手已保存，也不重发。客户端仅保证本地消息幂等，用户主动重试仍可能再次产生服务商费用。

输入保存失败会如实显示存储错误并保留进程内编辑内容；进程结束后只能恢复最后成功写入的加密版本。临时内容不会进入数据库、DataStore、文件、Bundle、SavedStateHandle 或后台任务。
