## 0. 工作规则

1. **一个工作包一个分支、一个 PR**，分支名为 `android/<编号>-<短名>`。提交信息遵循仓库现有风格（`feat:`、`fix:`、`docs:`）。
2. **`SKILL.md` 只读**。它受校验器的 5000 字符限制，并且是恋爱 Skill 的内核。其他场景的规则写在 App 的场景层（`app-prompt/scenes/`）中。新增的知识文档放进 `references/`。
3. **视觉边界**：页面中禁止硬编码颜色、字号、圆角、间距，只能使用 `JunshiTheme` 和 designsystem 组件。缺少组件时按 04 文档的风格补一个基础版本，并在 PR 中列出。
4. **文案**：所有界面文字放在 `strings.xml` 中，口吻以 02 文档第 10 节为准。
5. **隐私红线**：release 构建中不打印用户输入、聊天记录、模型回复和 API Key；不接入第三方统计 SDK；临时问问不落库；截图不上传。
6. **测试先行**：验收条件中写了「测试」的，必须有自动化测试；PR 描述中列出运行的命令和结果。
7. **不确定就停**：遇到合规、模型服务商选择、许可证、知识内容的价值判断时，保留负责人审阅门禁，不自行发布或合并；工程工作可按已确认的 05 修订继续。
8. 涉及界面的 PR 附上截图测试的输出。
9. **测试数据只能使用虚构内容**，包括截图。不要提交任何真实的聊天记录。

### T02 新增知识文档

### T13 领域模型与契约

位置：`core/domain`。

- 实现 01 文档第 8.4 节的契约，以及第 8.5 节的全部实体；`RelationType`、`Goal` 的枚举值与 01 文档一致。
- 请求闭环：`RequestMode = FULL_ANALYSIS | REWRITE_REPLY`；AnalysisRequest 增加 mode、parentAnswerId?、originalAnswer?、inputRevision。`AnalysisRun.requestId` 唯一并记录状态及目标会话；`Message.id` 唯一，requestId 为关联，用户与助手可共享，每请求至多一个当前助手结果。
- 同输入同操作失败重试复用 requestId；换口吻、调风格、改目标用新 ID 并关联原答案。REWRITE_REPLY 仅合并 REPLY／ALT；发现危机必须提高安全级别且隐藏普通策略，不可降低安全级别。过期 inputRevision 或会话版本回调不覆盖当前答案。客户端只保证不重复落库，不保证远端不重复计费。
- 在 T25 前交付 App 与悬浮面板共用的应用锁／危机显示接口和可执行默认实现（默认锁关闭，启用后真实检查锁状态；危机优先隐藏普通策略），后续 T53／T55 扩展，不以空接口代替。

- `SectionParser`：处理流式片段，对于标记缺失、乱序、重复、截断、片段在标记中间被切断都能容错；`[[REPLY]]` 中的 `+++` 拆分为多条消息；`[[ALT]]`、`[[TIP]]`、`[[SCENE]]` 按 `|` 解析，格式不对时降级为纯文本。
- `StyleFeatureExtractor`（纯函数）：输入用户本人的消息列表，输出可统计的特征——平均句长、emoji 与表情包占比、常用语气词前 10 个、标点习惯（是否使用句号、是否常用「～」「！」）、单条消息比例、是否使用「您」。

验收（单元测试）：解析器的所有容错场景；记忆规则；风格特征在 3 组虚构样本上的输出符合预期；重试无重复消息、用户与助手同轮关联、局部改写不覆盖其他段、乱序回调不覆盖新结果、安全级别不被普通改写降低；锁定和危机默认实现可执行。

### T14 加密数据库与 Repository

位置：`core/data`。

- Room + SQLCipher；数据库口令随机生成 32 字节，用 Keystore 中的 AES-GCM 密钥加密后存入 DataStore。
- 导出 Room schema 到 `core/data/schemas/`，从第 1 版开始写迁移测试。
- Repository：`ContactRepository`、`ConversationRepository`、`ImportRepository`、`StyleRepository`、`MemoryRepository`、`PlanRepository`、`TipRepository`、`ConsentRepository`。
  - 按联系人查询的方法必须传入 `contactId`。
  - `MemoryRepository.apply()` 和 StyleRepository 全部来源（import／quiz／edited_reply）的样本及派生特征、描述、摘要持久化均在 Repository 事务中检查当前同意、暂停与撤回状态；不满足则拒绝持久化，只可当前会话内存计算。异步结果返回后重新检查 consentVersion 和 sourceRevision，不能凭请求发出时的旧授权写入。
  - StyleSample 增加 sourceContactId?、sourceImportId?、sourceMessageId?、sourceAnswerId? 外键、consentVersion、createdAt；导入与修改回复必须有可追溯来源，测验可无联系人。StyleProfile 记录 sourceRevision。删除联系人、导入或样本时，事务内删除关联样本，递增来源版本，使画像、提示词和摘要缓存失效；剩余样本重算前禁用旧画像，提交后删除关联文件。全局风格不可作为其他联系人的事实记忆。
- 临时会话与草稿、导入、原始截图、摘要、风格样本只保存在进程内存 `TemporarySessionStore`，不进入数据库、DataStore、文件、SavedStateHandle／Bundle 或后台任务输入；网络失败可在进程存活期间恢复，进程结束即清除并提前告知。只有用户主动保存联系人会话后才幂等迁移选定内容。正式敏感草稿存加密数据库；DataStore 只存非敏感偏好及加密密钥包装值。

验收（测试）：联系人隔离、撤销规则；import／quiz／edited_reply 分别覆盖未同意、暂停、撤回、异步返回时授权或来源版本改变，断言样本与派生画像均不落库；临时导入后终止重启无恢复及持久痕迹，正式草稿可恢复，主动迁移不重复。合成唯一标记删除来源后数据库、画像、导出、后续请求均不含该标记；删除文件并重算剩余画像。

### T25 场景识别与完整答案卡

### T32 截屏会话与单帧捕获

- 状态机：OFF → REQUESTING_PERMISSION → STARTING_SERVICE → READY → CAPTURING → RECOGNIZING → ANALYZING → READY；任何状态可经 STOPPING → OFF。用户同意投屏后，启动声明 mediaProjection 类型及权限的 FGS，再获取 MediaProjection，注册 Callback；每会话仅创建一次 VirtualDisplay，停止后必须新授权，不复用旧授权／会话。
- 会话期间创建 `VirtualDisplay` + `ImageReader`。**平时调用 `VirtualDisplay.setSurface(null)` 暂停渲染**；用户点击悬浮球时恢复 Surface，取一帧后再次暂停，以节省电量。
- 截取前先隐藏悬浮球和面板，等下一帧画面刷新后再截取，确保截图中不包含 App 自己的界面。
- 无有效画面提示「暂时没能读取画面」，可检查共享应用或重试；黑屏不能断言禁止截图，区分正常深色空白、无新帧、共享范围错误与受保护页面。确认受保护时提示复制可分享文字或导入已有文件；不绕过保护，不送纯黑帧给模型。
- 默认 10 分钟未操作超时（可设 5 / 10 / 30 分钟）。系统停止、锁屏、其他投屏接管、撤销、超时及主动关闭走同一清理：停止取帧，释放 Image／ImageReader／VirtualDisplay／Surface，清空未用帧，使会话 ID 和旧帧／在途结果失效，移除悬浮窗，停止 FGS 与通知。清理可重复调用；从 App 或磁贴重开并新授权。
- 「再往上截一屏」：用户在聊天应用中往上翻一屏后点击，再截一帧，用 T22 的去重逻辑把两屏拼成一份导入。

### T43 长期记忆

按 02 文档第 2 节和第 6 节实现：首次出现值得记住的信息时才询问同意；写入后显示提示并可撤销；记忆页分组展示，可以编辑、删除、标注「这条不对」；暂停、恢复、撤回同意、全部清空。

验收：拒绝同意时 `[[MEMORY]]` 被忽略；达到配额时替换优先级最低的条目；被标注为不对的内容不会再次写入；注入提示词的记忆只属于当前联系人。

## 7. M5 · 学会它

### T51 技巧点拨、技巧本与习惯提醒

- 答案卡底部显示 TipCard：技巧名称、一句话解释、在本次回复中如何体现（高亮回复中的对应部分，如果模型给出了对应片段）。可以收藏到技巧本。
- HabitNotice：显示 `[[HABIT]]`，语气温和，每个联系人每天最多显示 1 次，可以关闭。
- 技巧本：按场景分组；同名技巧合并，并记录在哪些场景中用过。

验收：收藏、取消收藏、同名合并的测试；HabitNotice 的频率限制测试。

### T52 对练

- 从联系人详情或答案卡进入。军师扮演对方：使用聊天记录中对方的消息作为风格样本，按照对方可能的反应回复。
- 每轮流程：军师说一句（以对方的口吻）→ 用户输入回复 → 军师给出一行点评（好在哪里 / 可以怎样改）和一个更好的版本 → 下一轮。
- 用户可以设置难度：配合、正常、难搞。
- 对练内容默认不保存；结束时生成简短总结，用户可以选择保存到技巧本。
- 安全：对练中如果用户输入出现危机信号，停止对练并显示安全卡。

验收：对练提示词中包含对方的消息样本，不包含其他联系人的内容（快照测试）；每轮点评的结构正确；危机信号能中断对练。

### T53 情绪与安全

按 02 文档第 3 节实现：EmotionSlider、平静模式、BreathingPrompt、「10 分钟后再看」、SafetyCard。

- 关键词库 `calm-keywords.txt`、`crisis-keywords.txt` 由 Codex 根据 `references/knowledge/17` 起草，在 PR 中列出，由项目负责人审阅。
- `assets/safety/hotlines.json`：首版只放 110 和 120，其他号码需项目负责人复核后再加入。拨号只使用 `Intent.ACTION_DIAL`。

复用 T13 的安全基础实现，与悬浮面板共用。验收：情绪打分 ≥ 8、关键词、模型返回 `caution` 都能进入平静模式；危机关键词在模型回答之前显示安全卡；危机状态下普通策略隐藏且不可继续显示；用户确认安全后的展示仍经统一安全规则处理。

### T54 跟进提醒

按 02 文档第 7 节实现：在「我发了」之后询问是否提醒（默认不勾选）；Android 13 及以上在这时才请求通知权限；WorkManager 一次性任务；免打扰时段延后；通知默认脱敏；点击后进入联系人对话并带出「对方回了吗？」和快捷操作（上传新截图 / 还没回 / 情况变了）。

验收：使用 WorkManager 测试工具验证调度、免打扰延后和取消；默认通知中不包含联系人代号。 后台调度普通权限以 02 §8 的中央表为准；工程记录须附选定 WorkManager artifact 的真实合并 Manifest 和相对前包的权限差异证据，不添加精确闹钟权限。

### T55 隐私：应用锁、伪装图标、清除

按 02 文档第 8 节实现。

系统往返按02§8的有界交接：立即策略的明确系统launch及同一当前捕获→真实私密面板最多30秒、不续期；普通Home、控制球、服务／通知不豁免。1／5分钟原单调期限不增加。须通过短往返可用、精确超期／取消／清除／迟到旧票据失效、真实外部UID捕获至安全私密面板及最后面板关闭后锁定的生产入口回归；不新增前台识别权限或平行锁权威。

验收：锁定后最近任务中看不到内容；开启应用锁后，打开悬浮面板需要先解锁；全部清除先失效会话及请求版本、取消网络与提醒并关闭悬浮／投屏，再清数据库、文件、缓存、偏好、密钥包装及密钥，回到欢迎页；清除期间生成中的迟到结果不能重建资料，重启仍为空；Manifest 中只声明 02 文档第 8 节和第 16 节列出的权限。
