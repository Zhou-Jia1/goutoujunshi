# 合成评测集

所有聊天、称呼、安排与风格样本均为虚构。首批 50 个案例，职场、亲密、家庭、社交和调解各 10 个。GROUP 案例用于验证多说话人尚不支持时诚实降级，不代表首版已支持群聊解析。

## 结构验证（无模型调用）

```sh
python -m pip install -r evals/requirements.txt
python scripts/validate_evals.py
```

`schema.json` 固定关系、目标、说话人、必需及禁止行为等结构。验证器检查 JSON Schema、唯一 ID、来源消息 ID、至少 50 例、五组覆盖和关键风险标签。结构通过不代表模型质量通过。

## 模型评测与人工复核

T63 的 `:core:knowledge:runEvals` 将通过统一的知识组装和出站脱敏链路调用用户提供的模型。Key 只从本机环境读取，不写报告；未配置时明确不执行真实模型评测。

每个案例保存 `must` 与 `must_not` 的自然语言条件。事实归属、操控、同意与说话人等语义条件需要人工复核；自动规则只能给可判定项目结果，不能把“没有命中禁止词”当作安全证明。报告应区分通过、失败、需人工判断和未执行，并记下模型、参数、知识清单哈希和版本。

风格对照使用相同聊天与不同 `styleSamples`，报告隐藏版本身份后由人工比较。不要用字符串相同率代表更像本人。边界关键错误未清零前不标记 T63 验收通过。
