# 亲密场景（负责人待审稿，未获内容发布批准）

本场景以只读 SKILL.md 的核心原则、证据与安全边界为准，直接引用，不复写问卷或核心流程。App 协议覆盖首次建档默认流程：先处理本轮需求；档案、记忆和风格持久化须独立同意，不强制提供人格或评分。
关键变量：CRUSH/PARTNER/EX、双方明确表达、持续互惠、投入和兑现、同意与拒绝、现实可行性、用户目标和风险承受度。不以身份或性别推断角色，不凭一次回复读心。

每轮目标在核心原则下的场景适配：
- REPLY：按 SKILL.md 的一句话回复规则，回应当前消息的一个主动作。
- REPORT：共享计划、近况和影响，不把伴侣当审批者，不默认报备义务。
- ASK_HELP：具体说明支持需求与可选择范围，不以爱为条件索取。
- DECLINE：分清拒绝时间或方式与拒绝关系，表达真实意愿。
- APOLOGIZE：为具体行为担责并给补救，不用自我贬低交换原谅。
- CLARIFY：核对原文和理解差异，不预设背叛或替对方解释。
- COMFORT：先听见情绪，再征求是否需要建议。
- ADVANCE：仅在无明确拒绝且互惠允许时适用核心的主动原则。
- INVITE：可退出的具体邀约；按核心拒绝信号及时停止。
- BOUNDARY：清楚表达同意范围、拒绝及撤回权，不把沉默当同意。
- ICEBREAK：真实承认尴尬并轻量转场，不编造理由或冷读人设。
- REPAIR：根据核心修复边界，看持续行动与兑现，不承诺必然复合。
- MEDIATE：先确认用户是一方还是第三方，需要时采用调解场景规则。
- CLOSE：尊重结束意愿和停止联系，不以告别为借口持续施压。

禁忌与安全退出直接遵循 SKILL.md；出现家暴、胁迫、跟踪、威胁、自伤或伤人风险时停止关系推进，安全知识优先，明确拒绝后不继续追求。安全优先于修复或调解目标。
